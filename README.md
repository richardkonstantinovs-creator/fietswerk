# FIETSWERK — фазы 0, 1 и 2

Реализация по `FIETSWERK SPEC.md`. Фаза 0 — прототип для выяснения требований,
фаза 1 — рабочая версия для одного магазина, фаза 2 — «деньги магазина»
(occasions, комплаенс, абонементы, экспорт в бухгалтерию).

```
app/                        PWA: React + Vite + TypeScript + Tailwind
  src/lib/                  данные, деньги, workflow, коды бирок, QR, принтер, сканер, offline
  src/lib/rooster.ts        недели, смены, часы и овертайм — чистые функции под тестами
  src/lib/printer/          BLE-драйвер cat-printer за интерфейсом print(job)
  src/i18n/                 nl.json + en.json (620 ключей) + провайдер
  src/screens/              25 экранов, см. таблицу ниже
  scripts/check-i18n.mjs    CI: ни одной строки текста в JSX + паритет словарей
  public/sw.js              сервис-воркер: магазин работает при пропаже wi-fi
tools/printer-probe.html    опознание принтера (раздел 9.3) — запускать ПЕРВЫМ
```

## Запуск

```bash
cd app
npm install
npm run dev        # http://localhost:5173
npm run check      # типы + i18n + линтер + 93 теста
npm run build      # прод-сборка (сервис-воркер работает только в ней)
```

Node 20.19+ или 22.12+. Если после `npm install` падает `@rolldown/binding-*`
или `@oxlint/binding-*` — известная проблема npm с optional-зависимостями:
`npm install --no-save @rolldown/binding-darwin-arm64 @oxlint/binding-darwin-arm64`.

**Вход:** пин-коды демо — `1111` Harm (владелец), `2222` Sanne (механик),
`3333` Bram (приёмка), `4444` Lieke (механик), `5555` Douwe (суббота).
Автовыхода нет (раздел 2.2): вошли утром — работаете весь день.

Данные живут в `localStorage` браузера и засеваются голландскими демо-данными:
30 клиентов, 46 велосипедов (40 клиентских + 6 occasions), 25 нарядов, 35 позиций
склада, 3 поставщика, 2 заказа, 8 абонементов, счета и оплаты. Кнопка сброса —
на экране `Overzicht`. Supabase подключается **внутри `src/lib/db.ts`**, экраны
при этом не меняются.

## Навигация

Одна оболочка, две раскладки — точка переключения `sm` (640px).

- **Телефон.** Шапка сжата до одной полосы статуса (принтер + сохранение,
  раздел 9.7 и 8.8). Навигация — фиксированная нижняя панель на три ячейки:
  `Werkplaats`, `Scannen`, `Meer`. У каждой иконки подпись 16px, ячейка 60px.
  `Meer` открывает полноэкранный список остальных экранов плюс язык и выход.
- **Планшет и ПК.** Нижней панели нет, вся навигация в шапке одной строкой,
  седьмая кнопка `Meer` открывает то же окно.
- Кнопки `Meer`, нижней панели и шапки берут пути из трёх массивов в начале
  `src/components/Layout.tsx` — `TABS`, `NAV`, `MEER`. Больше нигде.
- Высота нижней панели живёт в `--tabbar` (`src/index.css`) и действует только
  внутри `.has-tabbar`, то есть в оболочке магазина. `PrimaryBar` встаёт
  ровно над ней (`bottom-app`), содержимое получает отступ (`pb-app`).
  Экран `/W/:code` вне оболочки — там панели нет и главная кнопка внизу.

## Фаза 1 — что добавлено

- **Роли и вход по пин-коду.** Отчёты и омзет видит только владелец.
- **Склад запчастей.** Поиск по названию/SKU/EAN/ячейке, красная плашка
  `Bijna op` ниже минимума, коррекция остатка, полная история движений.
  Деталь на наряд списывается со склада одним нажатием.
- **Заказы поставщикам.** `Bestellijst maken` собирает всё ниже минимума и
  группирует по поставщикам; повторный вызов не создаёт дублей. Заказ детали
  прямо из наряда переводит его в `wacht_op_onderdeel` и запоминает, **чего**
  он ждёт. Приём: скан EAN на коробке закрывает строку заказа, поднимает
  остаток и сообщает, какие наряды можно продолжать. Строка, за которой стоит
  клиент, закрывается раньше строки пополнения склада.
- **Уведомления.** Пять NL-шаблонов (gereed, offerte, onderdeel, herinnering,
  onderhoud), WhatsApp click-to-chat и e-mail; каждое отправление пишется в
  `notifications` и в таймлайн наряда.
- **Оплаты и счета.** `payments` + `invoices` с нумерацией `F-2026-0001`,
  печатный счёт (сохранение в PDF — через диалог печати браузера).
- **Офлайн.** Сервис-воркер кеширует оболочку, индикатор в шапке говорит
  человеческим языком: `Alles opgeslagen` / `3 wijzigingen wachten op internet`,
  очередь `outbox` уходит сама, когда сеть возвращается. PWA ставится на
  домашний экран (manifest + иконки).
- **Бирки на аккумуляторы** (раздел 8.6): у аккумулятора свой QR-код, который
  ведёт на тот же наряд; журнал `принят → на зарядке → снят → выдан` для
  страховой. Отдельного экрана `Accus` больше нет — всё живёт на наряде.

## Фаза 3 — рабочий календарь и часы

- **Rooster.** Неделя целиком: на планшете и ПК — таблица работники × 7 дней,
  на телефоне — те же данные списком по дням. Нажатие на ячейку ставит смену
  (от, до, перерыв, заметка), кнопка `Ook maandag t/m vrijdag` раскидывает её
  на всю рабочую неделю и **не создаёт дублей** на днях, где смена уже стоит.
  Отпуск, больничный и отгул закрывают дни целиком.
- **Uren.** Три числа на человека: `Gepland`, `Gewerkt`, `Overwerk`. Овертайм
  считается ровно так, как решил владелец: **факт минус план**, без правил CAO
  и без автоматического вычитания перерыва. Неделя или месяц, раскрытие по дням,
  ручной ввод и правка любой записи — с пометкой, что час поставлен рукой.
- **Klokken по NFC.** Метка у двери содержит ссылку `…/klok?tik=1`. Телефон
  касается метки, браузер открывает страницу, и приход или уход записывается
  сам — выбирать между «пришёл» и «ушёл» не нужно, система знает, что дальше.
  Второе касание в течение 90 секунд ничего не удваивает; ошибочное касание
  отменяется кнопкой `Toch niet`. На той же странице владельцу показывается
  ссылка для программирования метки и QR-код той же ссылки — на случай, если
  метка отвалится.
- **Забыл отметиться.** Если смена осталась открытой дольше 14 часов, система
  **не придумывает** время ухода: старая запись остаётся открытой, новый день
  начинается с чистой записи, а на `Uren` висит предупреждение и кнопка
  «Rechtzetten». Под этим лежит зарплата — угадывать нельзя.
- **Beschikbaarheid.** Работник отмечает по дням «могу» / «не могу» (можно
  с окном времени). Это пожелание, а не смена: расписание по-прежнему делает
  владелец, а пожелания подсвечиваются прямо в ячейках календаря.
- **Medewerkers.** Владелец сам добавляет человека (имя, роль, пин-код) и
  сам убирает — без звонка разработчику. «Уволить» — это **не удалить**:
  имя уходит из расписания и из списка входа, но отработанные часы остаются
  на месте, потому что за них уже заплачено, и человек по-прежнему виден на
  табеле того месяца, который он отработал. Полностью стирается только имя,
  за которым нет ни одной смены и ни одного часа — опечатка сегодняшнего утра.
  Пин-коды уникальны: два одинаковых означали бы, что один входит под другим.
  Себя и последнего владельца из системы не выключить.
- **Экспорт для бухгалтера.** CSV в том же формате, что и счета: точка с
  запятой, запятая в числах, даты `dd-MM-yyyy`. Строка на смену, рядом
  плановые часы и разница, плюс колонка «отредактировано вручную».

## Фаза 2 — что добавлено

- **Occasions с реальной маржой.** Считается то, что магазин сам не считает:
  `цена − закупка − детали − (минуты × себестоимость часа)`, плюс дни на складе.
  Себестоимость часа — отдельная настройка (`labor_cost_cents_per_hour`, €28).
- **DOR / ст. 437 Sr.** Форма закупки не сохранится без framenummer, отметки
  «видел удостоверение» и «проверил на stopheling.nl». `sellable_from` считается
  как дата + 5 рабочих дней, и до этой даты система **блокирует** перевод в
  `te_koop` и продажу.
- **Margeregeling.** НДС = (продажа − закупка) × 21/121; проверено тестом на
  примере из спецификации (€200 → €300 = €17,36). На маржинальном счёте НДС
  **не указан отдельно** — это отдельный шаблон. При закупке от €500 система
  требует и печатает **inkoopverklaring** в двух экземплярах.
- **Невостребованные велосипеды.** Группы 14 / 30 / 60 / 90 дней и цепочка
  доказательств: 1-я напоминалка → 2-я → заказное письмо → срок истёк.
- **Экспорт в бухгалтерию.** CSV для Moneybird, e-Boekhouden и SnelStart:
  точка с запятой, суммы через запятую, даты `dd-MM-yyyy`, отдельная колонка
  `margeregeling`. Свою бухгалтерию не строим — это анти-скоуп.

## Демонстрация: что показывать по порядку

**Фаза 0 (60 секунд на приёмку).** `Nieuwe fiets aannemen` → телефон
существующего клиента → его велосипед → чип `Lekke band achter (derailleur)`
(25 мин и цена подставились) → `Akkoord tot € 60` → 2 фото → `Opslaan`.
Код бирки выдан, QR на экране, бирка и afhaalbon ушли в печать. Переключить
`NL → EN`: интерфейс английский, суммы `€ 1.234,50` и даты `01-09-2026` прежние.

**Фаза 1 (деталь и деньги).** На наряде `Onderdeel bestellen` → выбрать деталь
и поставщика → наряд ушёл в `wacht_op_onderdeel` с текстом, чего он ждёт.
`Bestellingen` → сканировать EAN коробки → «W7K-3QM может продолжать».
Дальше `Gereed melden` → `Bericht: fiets is klaar` (WhatsApp) → `Afrekenen` →
счёт `F-2026-…` печатается.

**Фаза 3 (люди и часы).** `Rooster` → неделя целиком, нажать пустую ячейку
субботы у `Douwe` → 09:30–17:00 → `Opslaan`; ячейка заполнилась, недельная
сумма справа выросла. `Beschikbaarheid` под своим именем → «Ik kan niet» на
пятницу — у владельца в этой ячейке появилась красная пометка. `Klok` →
`Ik begin`, через минуту `Ik ga naar huis`; `Uren` показывает
`Gepland · Gewerkt · Overwerk` и отдаёт CSV бухгалтеру. Открыть
`…/klok?tik=1` — это ровно то, что делает касание NFC-метки: отметка
поставлена без единого нажатия, рядом кнопка «Toch niet».

**Фаза 2 (маржа и закон).** `Occasions` → `Fiets inkopen`: без framenummer,
ID и stopheling форма не сохраняется; после сохранения — «продавать можно с
такого-то числа». На карточке — вложено / вопрос-прайс / **echte marge**.
`Rapporten` → невостребованные по возрасту, НДС с маржи за квартал, выгрузка CSV.

## Definition of done для печати (фаза 1) — требует железа

```
1. printer-probe подтвердил семейство и протянул бумагу
2. «Opnieuw afdrukken» на наряде → бирка выходит целиком, без полос
3. QR считывается с 25 см с первой попытки, 10 раз из 10
4. Код W7K-3QM читается с расстояния вытянутой руки
5. Выключить принтер: приёмка сохраняется, задание встаёт в очередь,
   в шапке «Printer niet verbonden», после включения печатает само
```

Порядок опознания принтера (раздел 9.3): открыть `tools/printer-probe.html`
в Chrome или Edge → `Printer zoeken` → посмотреть сервисы → `Papier doorvoeren`.
Поехала бумага — семейство cat-printer подтверждено. Нет сервиса `ae30` —
скопировать дамп и остановиться, протокол другой.

## Честные ограничения

- **NFC с личных телефонов требует сервера.** Сейчас `/klok` работает на
  устройстве, где человек вошёл в приложение: планшет у входа со сменой
  профиля, либо телефон работника — но тогда у каждого телефона своя база в
  браузере, и владелец на своём планшете этих отметок не увидит. Как только
  в `src/lib/db.ts` встанет Supabase, тот же экран и та же метка начинают
  работать так, как задумано, без переписывания.
- **Метку и QR можно скопировать.** Ссылка со стены фотографируется, и
  теоретически можно «прийти на работу» из дома. Для магазина на пять человек
  это ловится глазами и колонкой «кто сейчас внутри» на `Overzicht`; если
  понадобится строже — код, меняющийся каждые 30 секунд на экране планшета.
- **Сервера ещё нет.** Всё лежит в браузере. `src/lib/db.ts` — единственное
  место, куда встанет Supabase; `outbox` — готовая точка подключения синхронизации,
  но пока она помечает записи синхронизированными локально.
- **Офлайн** сделан на сервис-воркере + `localStorage`, а не на IndexedDB.
  Для одного магазина объёма хватает; при переезде на Supabase кеш переедет
  вместе с адаптером.
- **PDF** — через диалог печати браузера («Сохранить как PDF»), без своей
  PDF-библиотеки.
- **DOR и stopheling.nl** — ручная проверка с фиксацией факта и времени.
  Публичного API нет, экспорт в DOR заказчику не обещаем.
- **Печать не проверена на вашем экземпляре Karsten** — драйвер написан по
  открытым реализациям; сначала `printer-probe`.
- Фаза 3 (аренда, каталоги поставщиков, онлайн-запись, Mollie, полноценная
  касса) и анти-скоуп из раздела 13 не трогались.

## Что уточнить у владельца

- Часовая ставка мастерской: сейчас €55/час **без НДС** (≈€66,55 с НДС).
- **Себестоимость часа** для маржи occasions: сейчас €28/час — цифра из головы.
- Нормо-времена раздела 11 и лимит по умолчанию €80.
- Ширина рулона (код рассчитан на 384 точки / 48 мм) — измерить линейкой.
- Техника за стойкой: Windows + Chrome/Edge? Bluetooth есть? Какие телефоны
  у сотрудников (раздел 9.4).
- Сколько рабочих дней держать б/у до продажи в их муниципалитете (сейчас 5).
- Стоит ли у них CycleSoftware / Lightspeed / EsGarage — тогда надстройка,
  а не замена (раздел 5).
- **Перерыв:** вычитать ли его автоматически при смене длиннее 5,5 часов, или
  оставить как сейчас — руками. Сейчас плановый перерыв 30 минут стоит в смене,
  фактический ставится вручную.
- **Овертайм по неделе.** Сейчас считается по дню (факт − план). Если у людей
  контракт «X часов в неделю», нужна цифра контракта на человека.
- **Кто ставит расписание.** Сейчас только владелец. Нужен ли доступ приёмке?
- Модель телефонов у сотрудников: NFC-ссылка открывается сама на iPhone XS+
  (iOS 14+) и на Android; на более старых iPhone метку придётся заменить QR.
